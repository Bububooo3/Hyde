# Hyde Image Decomposer

The standalone `apps/decomposer/` workspace builds with `npm run build -w @hyde/decomposer` and previews with `npx vite preview --config vite.decomposer.config.ts`. It runs locally, uses a worker for deterministic image analysis, and needs no account, model weights or hosted service. Open `decomposer.html` in the preview server, import PNG/JPEG/WebP references, analyze, correct regions and parts, compare the actual Hyde render, and save the recoverable `.hydecomp` working document. Native `.hyde` projects and `.hyproj` assemblies are emitted through Hyde's SDK command transactions and archive codec.

## Scriptable workflow

`src/decomposer/index.ts` exports `DecompositionSession` for conventional TypeScript callers. `importSources`, `analyze`, `inspect`, `execute`, `compare`, `saveDocument`, `openDocument`, `exportHyde` and `close` use the same model as the GUI. Edits have an `expectedRevision`, commit atomically, and support dry-run. Binary masks are staged through handles. The source byte and decoded-pixel getters return copies.

The `hyde-decompose` executable is built at `apps/decomposer/dist/cli/hyde-decompose.mjs`. It writes JSON to stdout and binary artifacts only to explicit paths. Existing destinations are refused unless `--overwrite` is given; replacement retains a `.bak` sibling.

```sh
node apps/decomposer/dist/cli/hyde-decompose.mjs import --source art.png --output art.hydecomp --json
node apps/decomposer/dist/cli/hyde-decompose.mjs analyze art.hydecomp --output art.hydecomp --overwrite --mode animation-ready --json
node apps/decomposer/dist/cli/hyde-decompose.mjs inspect art.hydecomp --target regions --limit 25 --json
node apps/decomposer/dist/cli/hyde-decompose.mjs inspect art.hydecomp --target tile --view evidence --region REGION_ID --bounds 0,0,256,256 --output evidence.png --json
node apps/decomposer/dist/cli/hyde-decompose.mjs compare art.hydecomp --native --overlay residual.png --json
node apps/decomposer/dist/cli/hyde-decompose.mjs export art.hydecomp --format hyproj --output art.hyproj --json
```

For multiple references, `import --request manifest.json` accepts `{ "name": "Art", "mode": "appearance", "sources": [{ "path": "primary.png", "role": "primary" }, { "path": "side.png", "role": "alternate-view" }] }`. `edit --request edits.json` accepts `{ "expectedRevision": 1, "edits": [{ "op": "part.rename", "partId": "...", "name": "Arm" }] }`. An optional `masks` array supplies raw binary 0/1 files with `name`, `path`, `width` and `height`, plus optional `alphaPath` containing 0–255 coverage within the binary mask; a `region.refineMask` edit refers to that name as its handle. `inspect --target tile` writes an exact, unscaled PNG of `source`, `mask`, or `evidence` (source with the selected mask boundary in red). A tile is limited to 512 × 512 pixels; JSON returns metadata without image bytes. These are source diagnostics, while `compare --native` builds a neutral-pose `.hyde` candidate and renders through Hyde's private offline Chromium host. Its JSON omits the binary residual overlay; `--overlay` saves it separately.

## Source and quality contract

Edge sensitivity is a recorded setting from 0.25 to 2. Higher values keep weaker paint boundaries separate; lower values allow more smooth-band merging. The default of 1 retains older v1 behavior. The staged regeneration panel previews this alongside color granularity, minimum feature size, thin-line preservation and path tolerance before committing full-resolution analysis.

The `.hydecomp` ZIP stores exact original bytes, canonical decoded RGBA, masks, geometry, user edits, locks, lineage and correspondence with member hashes. PNG decoding is shared by Node and browser; JPEG/WebP use the local Chrome or Chromium decoder, with canonical pixels persisted so a reopened document is stable. The CLI browser decode and reopen path is exercised for both formats. An embedded PNG ICC profile or non-sRGB gamma/chromaticity tag produces a persisted warning: those transforms are retained in the original bytes but are not applied to deterministic analysis pixels. SVG import is currently unsupported. Each reference is analyzed separately; alternate poses remain evidence and never become motion keys or clips.

Appearance-first and animation-ready use the same region graph with different deterministic settings. Connected color/alpha regions become separate editable paths; broad shared boundaries can group multiple paint regions into one logical part. Authentic source crops back textured paths. A first appearance pass with at least 100 mostly tiny regions tries coarser grouping once; it adopts the candidate only when region count falls substantially and mask agreement stays within one percentage point, and records the chosen settings and a diagnostic. Explicit settings override this retry. Interior holes are fitted as independently editable native contours. If a hole cannot fit Hyde's contour limits, native export requires explicit `allowHoleApproximation` approval and reports the remaining raster-alpha approximation. Very busy images that yield mostly tiny fragments are reported as insufficient structure and require guided correction before native export.

The native comparison reports thresholded silhouette IoU, boundary distance, overlap sRGB error, missing/extra/halo pixels and structural complexity. It compares canonical source pixels with an actual Hyde browser-rendered PNG at source resolution and writes a colored residual overlay. This is objective pixel evidence, not a claim of subjective part usefulness. Synthetic rights-clear fixtures and measured boundaries are in `tests/decomposer-synthetic-acceptance.md`; the acceptance inventory is in `docs/ACCEPTANCE.md`.

Current guided tools include mask brushes with editable radius and hardness, bounded color/edge-aware foreground/background seeds, editable path anchors and Bézier handles with optional edge snap, source zoom/pan, region split/merge, part assignment/rename/pivot/reparent/attachment, front/back relations, paired landmarks and source alignment, locks, regeneration and undo/redo. The add brush can expand an unlocked generated contour beyond its automatic rectangle, clipped to the source image; the revised bounds and mask remain recoverable and export as native Hyde geometry. A pinned manual contour must be unlocked and switched to its generated path before outward brush expansion. Soft brush coverage is stored per pixel beside binary contour topology in `.hydecomp` and survives undo/reopen; Hyde native export places that coverage in texture alpha within the editable shape. Regeneration review overlays amber current, teal proposed and red removed contours without mutating the document; the canvas preview is bounded to 64 contours and 8192 path points, with excess counted in the panel. Animation-ready analysis proposes a conservative two-pixel-inset hidden continuation only under a fully opaque enclosed foreground; each inferred path remains editable, visibly uncertain and individually suppressible/restorable without losing source evidence. Multi-reference matching ranks contour, color, size, neighborhood and optional declared alignment, preserves manual decisions, and leaves close alternatives unresolved. Animation-ready analysis also offers unapproved Fixed/Hinge parent and contact-pivot proposals when visible parts touch. The part inspector shows evidence, accepts or rejects each suggestion, and can independently lock the chosen attachment. Accepted attachments persist through `.hydecomp` reopen and native export. A temporary hinge/slider offset can be rendered through Hyde with authored joint limits using a disposable project copy; it never saves a pose or motion. A single still cannot establish joint type or motion limits, so these remain reviewable heuristics.

For a flat region, the selected-region inspector accepts a six-digit hex fill and offers **Reset generated color**. The `region.setColor` transaction stores the automatic estimate separately, keeps the correction through regeneration and `.hydecomp` reopen, and supports undo/redo. Mask and path remain independently regenerable. The fill exports as native Hyde geometry, including an uncertain inferred hidden region. Source-crop textured regions keep their source pixels and do not offer a flat fill edit.

In animation-ready mode, a manually confirmed same-part identity plus a declared affine alignment can produce additional proposed front/back evidence when pixels visible in the alternate still map under another primary region. When hidden inference is enabled, a small inset continuation can be generated beneath an opaque primary foreground as an independently editable inferred region; the alternate pixels constrain its footprint, while its color estimates the visible primary part. It never asserts actual unseen texture or motion. Actual Hyde rendering checks that this continuation leaves the primary pose intact. The selected-region inspector shows the measured evidence and can approve or reject the relation. A rejection is a manual decision that survives `.hydecomp` reopen and reanalysis and removes the generated continuation; approval permits it again. Preview regeneration after matching and aligning stills to inspect newly derived evidence.

Source pixels with low alpha immediately adjacent to a hard foreground component extend that region's editable path by one pixel and retain their authentic alpha in native Hyde rendering, even when general texture preservation is off. Isolated low-alpha marks remain below the segmentation threshold. The user can apply `region.featherOutside` with a bounded radius and strength to extend a generated contour into unoccupied neighboring pixels. The operation creates editable soft coverage, remakes the path, keeps original mask evidence and is undoable; source-transparent pixels use the region color as the fringe fill. A pinned manual path blocks this operation. Unlock the path and choose **Use generated contour** to explicitly discard the override in an undoable revision, then apply feather. Brush strokes still edit only the current region bounds. Native holes have editable anchors and handles in the editor and SDK. The enclosed-overlap rule does not recover general unseen surfaces or complex textures. Contact-based proposals do not infer Slider motion or joint limits. Broader visual-quality fixtures and bounded owner visual review also remain open.

A successful native export records a versioned mapping in the in-memory `.hydecomp` document: part, region and geometry IDs to Hyde IDs, normalized output options, warning codes, and SHA-256 fingerprints for the source snapshot and exact native bytes. Save the source document after export to retain this mapping. A later edit or regeneration invalidates it; a failed export leaves the last mapping intact. The CLI returns the mapping as JSON without silently overwriting the source file.

Cross-reference identity is a correspondence annotation between separate stills. The UI names candidates by source and pixel location, marks unresolved matches, and requires an explicit manual confirmation for repeated shapes. Hyde export uses the primary construction pose and does not create motion from these references. Animation-ready sources below 96 pixels on either side receive `LOW_SOURCE_RESOLUTION`: a rotated contour extracted from pixel art can retain visible stair steps. The 64×72 and 192×192 character comparisons in `docs/quality/` show this source-detail boundary using actual Hyde frames.

Selecting an additional reference opens a side-by-side still comparison above the editing canvas. It labels which image supplies the primary construction pose, explains that matching and affine alignment provide evidence only, and keeps automatic motion out of the workflow. Fit-size canvas and native Hyde preview images use smooth display scaling; explicit pixel zoom uses nearest-neighbor display so individual source pixels remain inspectable. Display scaling does not modify exported geometry or source pixels.
