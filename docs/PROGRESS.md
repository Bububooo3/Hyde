## Agent SDK and Image Decomposer handoff

**Status (2026-10-26):** Both products meet the specifications' bounded v1 completion thresholds. Work is in the existing `C:\Users\rscot\Downloads\Story-Editor-Project` repository, on local `main`; no push, package publication, remote change or deployment occurred. The later authorized Story Studio backlog is tracked above.

**Architecture:** `packages/sdk/` and `apps/decomposer/` are independent npm workspaces inside Hyde. They share root `src/` model, evaluator, editing operations, renderer and native archive codec. The SDK works in Node without the editor; actual previews/exports use Hyde's browser renderer. The Decomposer is a standalone local GUI and CLI, stores recoverable `.hydecomp` documents, and exports editable `.hyde`/`.hyproj` through SDK transactions. Images never generate keyframes, clips or motion.

**Acceptance evidence:** The SDK's public fixtures cover every command category, a textured/masked two-scene story with camera, text motion, captions and audio, assembly clips/collisions, procedural motion, arrangement/folders, atomic rollback, undo, bounded inspection, CLI and restricted bridge. Story Studio opens, edits and saves SDK stories, which the SDK reopens. The Decomposer's curated fixture suite covers icon, multicolor prop, character, occlusion, textured/antialiased sticker, holes/islands, alternate views, repeated ambiguous parts, pixel art, busy input and malformed/resource inputs. Automatic first pass, guided corrections, non-destructive regeneration, optional cross-reference matching, manual articulation and native editable export pass Node/Chrome workflows. The owner found the fox useful, the smooth character pose plausible, and the revised multi-view explanation clear. The fox native render measures .99946 silhouette IoU; the 192px articulated source renders smoothly in a temporary Hyde pose.

**Verification:** Sequential integrated run: 82 test files and 432 tests passed, one file and six tests skipped; two later public SDK acceptance additions pass in the 6/6 focused file. **Documented limits:** Single-view hidden surfaces and joint types remain uncertain; the UI labels inferred geometry and requires manual approval for attachments. Unrepresentable contour cases use an explicit warned fallback. Low-resolution pixel art can stair-step when rotated; the high-resolution fixture does not. JPEG/WebP embedded color profiles can render differently between browsers and produce a warning. MP4/WebM depend on runtime codec support and were unavailable in the test Chrome. Full canonical pixels for the active source remain in UI memory under a 4-million-pixel input cap. These are quality/platform boundaries, not missing v1 workflows. Web Audio owns live time when available, with bounded effect-history reconstruction and finite tails; a monotonic visual clock keeps silent playback possible without it. Render optimization is a hint only; cached visuals invalidate on project, evaluated pose, texture, and font changes. No backend or accounts.
